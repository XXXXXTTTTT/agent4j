# 会话、工作区与模型池管理设计

## 目标

为 Agent4J Web 工作台建立清晰的会话生命周期、工作区唯一性和用户级模型配置能力，解决重复工作区污染、归档语义不清以及模型只能通过 `.env` 静态配置的问题。

## 会话生命周期

`ACTIVE` 会话出现在默认列表，可提交新轮次；`ARCHIVED` 会话保留全部轮次、Run 快照和审计记录，但默认列表隐藏，只在“已归档”筛选中显示。

新增 `DELETE /api/conversations/{conversationId}`。删除前必须由当前用户具备工作区 `OPERATOR` 权限。删除事务级联删除该会话的轮次，并删除这些轮次专属的 Run/Checkpoint 记录；工作区、工作区目录和工作区级长期记忆不删除。删除不可恢复，删除后读取返回“不存在或无权访问”。

归档不影响长期记忆；删除也不删除工作区级记忆，但后续新会话不会自动加载被删除会话的轮次上下文。

## 工作区唯一性与测试数据

工作区唯一键为当前用户、规范化绝对 `workspacePath` 和精确 `repositoryId`。创建时先查询该键，已存在则返回现有记录并更新显示名称，不再生成重复 UUID。列表在服务层按相同唯一键去重，保留 `updatedAt` 最新记录，兼容历史重复数据。

本地测试只使用固定 `agent4j-test` 工作区标识；测试创建的会话统一归档，不创建随机工作区。生产工作区删除不与会话删除绑定，避免误删项目目录。

## 模型组与 API 池

新增用户级配置实体：

- `ModelProvider`：`providerId`、显示名、Base URL、加密存储的 API Key、启用状态、并发上限、速率上限。
- `ModelEndpoint`：所属 Provider、精确模型 ID、能力集合、优先级、权重。
- `ModelGroup`：`groupId`、显示名、任务类型、端点列表、默认策略。

前端只接收 API Key 是否已配置和掩码，不返回密钥正文。用户在“模型设置”中维护 Provider、端点和模型组；对话栏只显示模型组名称，不直接显示密钥或内部 URL。

每个会话轮次可选择 `modelGroupId`，提交时持久化到轮次和 Run 状态。未选择时使用用户默认组。Router 先按优先级筛选启用端点，再按权重轮询；请求失败、超时或熔断时在同组内降级到下一个端点，所有端点失败才返回组级错误。跨组降级只允许使用组声明的 fallbackGroupId。

## API

- `GET /api/model-groups`：返回当前用户可用模型组和端点摘要。
- `POST /api/model-providers`、`PUT /api/model-providers/{id}`、`DELETE /api/model-providers/{id}`：维护 Provider，响应永不包含密钥正文。
- `POST /api/model-groups`、`PUT /api/model-groups/{id}`、`DELETE /api/model-groups/{id}`：维护模型组和端点绑定。
- `DELETE /api/conversations/{id}`：删除会话及其会话专属数据。

所有资源按当前用户隔离，未知 ID 返回统一 404，不泄露其他用户资源存在性。

## 前端交互

工作区下拉只显示去重后的工作区；每项显示名称和短路径，提供“工作区设置”入口。会话侧栏分为“进行中”和“已归档”，归档/删除操作放在会话上下文菜单，删除必须二次确认。

顶栏新增模型组选择器，显示当前组和可用端点数量；模型设置抽屉支持 Provider、端点和组编辑。提交轮次时把当前模型组 ID 写入请求，切换工作区时重新加载该用户的模型组和会话列表。

## 测试门禁

- JDBC 集成测试：归档保留轮次，删除级联轮次/Run，删除后不可读，工作区记忆表不受影响。
- 工作区测试：同一用户/路径/仓库创建返回同一记录，列表去重，路径不同或仓库不同不合并。
- 模型池测试：密钥脱敏、用户隔离、优先级/权重选择、失败降级和全端点失败错误。
- Controller 合约测试：精确 JSON 字段、权限和 404 语义。
- 前端测试：归档筛选、删除确认、工作区去重显示、模型组选择和配置表单。
- EDD：使用固定 `agent4j-test` 工作区执行至少三轮真实会话，验证归档后列表隐藏、重新筛选可见、删除后不可恢复；模型组选择在 Run 状态中可追踪。
