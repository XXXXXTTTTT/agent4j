# Agent4J 暖中性桌面工作台设计

## 目标

将现有 Agent4J 工作台重构为舒适、可扫描、适合持续编码工作的桌面界面。借鉴 Cursor 官网公开页面体现的暖中性主题、紧凑 chrome、低对比边界和面板层级，但不复制 Cursor 的品牌、字体、图标、资产或文案。

## 已确认问题

现有 `styles.css` 同时存在深色、浅色和末尾补丁三套规则。侧栏、消息、输入器、审批和检查器因此出现混合背景与低对比文字。固定四栏也让中心对话在常见桌面尺寸下过窄；活动栏只改变属性，不真正收纳上下文；原始模型请求和响应默认展开，干扰用户阅读最终回答。

## 视觉系统

本期只维护一套暖中性深色主题：

```css
--surface-base: #171814;
--surface-raised: #1d1f1a;
--surface-overlay: #252720;
--surface-hover: #2d2f28;
--border-subtle: #34372f;
--border-strong: #4a4d43;
--text-primary: #f1f0e9;
--text-secondary: #bebdb4;
--text-muted: #8c8d84;
--accent: #8ab4ff;
--success: #71c58c;
--warning: #e3b86b;
--danger: #ef8991;
```

`--accent` 只用于焦点、当前选择、链接和主提交动作。成功、审批和失败只使用小型状态点、标签或边框，不给整个区域铺色。UI 使用系统 sans，代码使用 Cascadia Mono/Consolas。常规控件圆角 6px，浮层 8px，禁止渐变与装饰性光球。

## 布局与交互

- 顶部 chrome 高度 44px，展示 Agent4J、当前工作区/会话和运行状态。
- 桌面大屏使用活动栏 48px、项目栏 248px、中心对话 `minmax(0, 1fr)`、检查器 380px。检查器可通过按钮收纳，中心对话拥有最小 560px。
- 1280px 以下自动收纳项目栏或检查器；760px 以下只显示一个主上下文，活动栏转为底部导航，输入区保持可见。
- 收纳状态是确定的：`1280px > width >= 900px` 默认收纳检查器、保留项目栏；`900px > width >= 760px` 默认收纳项目栏和检查器，只保留活动栏与中心对话；`width < 760px` 只渲染中心对话和底部输入区，活动栏固定在底部，项目与检查器通过活动按钮进入抽屉。收纳面板使用 `hidden`，并从 Tab 顺序移除；恢复面板时将焦点移到其标题。Terminal/Trace 的订阅仅在其 tab 激活或检查器打开时保留。
- 活动栏选中状态同时维护 `aria-current` 与可见焦点样式。切换到“对话”或“项目”会关闭检查器；切换到“运行证据”或“能力”会打开检查器并把焦点移动到标题。目标面板在 DOM 中保持可访问，但非目标低频面板可收纳，不再伪装成布局切换。
- 对话使用平面文档流：用户消息、Agent 主回答和最终结果最突出；计划、工具、代码、测试和原始模型请求成为紧凑事件行。原始请求/响应默认 `details` 折叠。
- Composer 是中心区底部单层工作面；模型组、工作区和发送按钮保持稳定位置。`/` 命令继续使用受治理命令目录，命令预览单独表达风险和审批。Trace 与 PTY 的连接保持为 Run 级事实流，避免收纳面板时丢失真实事件；其视觉组件只在检查器打开并选中相应 tab 时挂载。
- 侧栏错误必须在删除、归档、切换和搜索失败时保留可见反馈。

## 验收

官网证据来源为 `https://cursor.com/`，抓取日期为 2026-08-14；已保存 HTTP 200 页面源码至 `.tmp/cursor-home.html`，其中包含 `#f7f7f4`、`#14120b`、紧凑产品 chrome 与响应式网格信息。浏览器运行时无法启动，因此不声称已有官网截图；本项目的截图/渲染证据来自本地 Electron/Chromium。

必须通过前端全量测试与构建，并在 1440x900、1024x768、390x844 三个视口确认无水平溢出、无混合白色旧控件、输入器首屏可见、活动栏焦点清晰、证据可读。使用可复现的 Chromium headless 命令加载本地 Vite 预览，保存截图到 `.tmp/visual-acceptance/`，并在页面脚本中断言 `document.documentElement.scrollWidth <= window.innerWidth`、composer 可见、隐藏面板不含可聚焦元素。既有聊天、Markdown、MCP/Skill、模型组、Terminal、Diff、Trace、审批、图片工件和桌面导入回归测试必须继续通过。
