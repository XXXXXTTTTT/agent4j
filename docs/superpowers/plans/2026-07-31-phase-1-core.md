# Phase 1 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 初始化 Java 21 多模块工程，并交付可运行、可测试的图状态机内核和支持 OpenAI SSE 与 Function Calling 的 LLM 客户端。

**Architecture:** 根 Maven 工程聚合四个职责独立的模块，Phase 1 的行为集中在 `agent-core`。图引擎用不可变 record 传递状态并用虚拟线程逐节点调度；LLM 客户端用 `RestClient` 执行普通请求并按 SSE 事件边界读取流，两种 I/O 都显式运行在虚拟线程中。

**Tech Stack:** Java 21、Spring Boot 3.3.13、Spring `RestClient`、Jackson、JUnit 5、Spring Test、Maven 3.8.8。

---

## 文件结构

- `pom.xml`：父工程、Java 21、Spring Boot 版本和四模块聚合。
- `agent-core/pom.xml`：图引擎和 LLM 客户端依赖。
- `agent-rag/pom.xml`：RAG 模块边界。
- `agent-sandbox/pom.xml`：沙箱模块边界。
- `agent-web/pom.xml`：WebFlux 服务入口依赖。
- `agent-web/src/main/java/com/agent/web/AgentWebApplication.java`：Spring Boot 入口。
- `agent-core/src/main/java/com/agent/core/engine/*`：不可变状态、节点协议、路由协议、执行器和强类型异常。
- `agent-core/src/main/java/com/agent/core/llm/*`：消息模型、OpenAI DTO、同步与 SSE 客户端和强类型异常。
- `agent-core/src/test/java/com/agent/core/engine/*`：状态与图引擎行为测试。
- `agent-core/src/test/java/com/agent/core/llm/LlmClientTest.java`：HTTP、SSE 与 Function Calling 协议测试。

- [ ] **Step 3: 实现函数式接口与异常**

`GraphExecutionException` 保存失败节点名称和 cause；

- [ ] **Step 4: 实现 StateGraph**

`StateGraph(int maxSteps)` 拒绝非正数，创建
`Executors.newVirtualThreadPerTaskExecutor()`。所有构图方法返回 `this`；注册时
精确验证节点和路由目标。`execute` 在每步执行前检查熔断，将节点提交给虚拟
线程并等待结果，之后解析条件边或普通边；到达 `END` 返回最终状态。中断时
恢复调用线程 interrupt 标志，节点失败时保留原始 cause。`close` 关闭执行器。

### Task 4: OpenAI LLM 客户端

**Files:**
- Create: `agent-core/src/test/java/com/agent/core/llm/LlmClientTest.java`
- Create: `agent-core/src/main/java/com/agent/core/llm/LlmClientException.java`
- Create: `agent-core/src/main/java/com/agent/core/llm/LlmClient.java`

- [ ] **Step 1: 写普通响应与 Function Calling 失败测试**

用 `MockRestServiceServer.bindTo(RestClient.Builder)` 绑定本地请求期望。请求必须
命中 `/v1/chat/completions`、使用 POST、发送 `stream: false`，并包含函数工具
的 `name`、`description` 和 JSON Schema `parameters`。响应包含 assistant 的
`tool_calls`，断言 `finish_reason=tool_calls`、函数名和 arguments 字符串被精确
反序列化。

- [ ] **Step 2: 写 SSE 与错误传播失败测试**

返回 `text/event-stream`，内容包含两个 `data:` JSON 事件、空行边界和
`data: [DONE]`。断言 consumer 收到两个增量、执行 consumer 的线程为虚拟
线程且 `[DONE]` 不产生数据。另返回 HTTP 502，断言抛出
`LlmClientException` 且保留 cause。

- [ ] **Step 3: 运行目标测试并确认红灯**

Run: `mvn -pl agent-core -Dtest=LlmClientTest test`

Expected: 测试编译失败，精确原因是 `LlmClient` 与 DTO 尚不存在。

- [ ] **Step 4: 实现请求、响应和流式 DTO**

`LlmClient` 内创建公开静态 record：`ChatCompletionRequest`、
`ChatCompletionResponse`、`Choice`、`Usage`、`Tool`、`FunctionDefinition`、
`ChatCompletionChunk`、`ChunkChoice`、`Delta`、`ToolCallDelta`。集合字段使用
防御性复制；`tool_choice`、`finish_reason`、`prompt_tokens`、
`completion_tokens`、`total_tokens` 使用 `@JsonProperty` 精确映射；所有响应
DTO 使用 `@JsonIgnoreProperties(ignoreUnknown = true)`。

- [ ] **Step 5: 实现虚拟线程 HTTP 与 SSE**

`complete` 把 `stream` 改为 false 后通过 `RestClient.retrieve` 读取完整 DTO。
`stream` 把 `stream` 改为 true 后通过 `RestClient.exchange` 获取响应流，显式
检查 HTTP 状态，并按 SSE 空行边界组合一个事件的全部 `data:` 行。事件数据
等于 `[DONE]` 时终止，否则调用 `ObjectMapper.readValue` 后传给 consumer。
两种方法都通过私有 `runOnVirtualThread` 提交到客户端虚拟线程执行器。
